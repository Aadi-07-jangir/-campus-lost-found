Campus Lost & Found

AI-Powered Item Recovery System — Methodology & Implementation Report

Section 3: Methodology

3.1 Problem Approach

We use a dual-model AI pipeline that combines computer vision and natural language processing to automatically match lost items with found items based on visual and textual similarity, eliminating the need for manual searching.

3.2 AI Models Used

Model Purpose Output
BLIP
Salesforce/blip-image-captioning-base		 Automatically generates natural-language captions from uploaded item images (e.g., "a black leather wallet on a bench") Text caption (up to 100 tokens)
CLIP
openai/clip-vit-base-patch32		 Converts images and text into a shared 512-dimensional embedding space for similarity comparison 512-dim normalized float vector

3.3 Matching Pipeline

📷 User Uploads Image
↓
BLIP → Auto-generated Caption
↓
CLIP → 512-dim Image Embedding
↓
Fusion: 95% Image Embedding + 5% Text Embedding (caption + user description)
↓
L2 Normalization → Final Embedding stored in DB
↓
Cosine Similarity vs. all opposite-type items (lost↔found)
↓
Matches above 0.65 threshold → Surfaced to user, ranked by score

3.4 Why This Approach?

  • Visual-first matching — Images are more reliable than user descriptions, which can be vague or inconsistent
  • Embedding fusion — 95/5 weighting ensures exact image matches aren't impacted by varying text descriptions
  • Pre-trained models — BLIP and CLIP are trained on millions of image-text pairs, providing strong zero-shot generalization without needing custom training data
  • Local cosine similarity — Matching computation is done client-side in Dart for instant results without server latency

3.5 Model Links

  • BLIP: https://huggingface.co/Salesforce/blip-image-captioning-base
  • CLIP: https://huggingface.co/openai/clip-vit-base-patch32

Section 4: Implementation

4.2 Implementation Steps

  1. Database Design & Setup — Designed PostgreSQL schema with three tables (items, users, messages) on Supabase, with Row Level Security (RLS) policies for data protection and a storage bucket for item images.
  2. AI Server Development — Built a FastAPI server with 6 endpoints: /health, /caption, /embed, /embed-text, /match-bulk, and /process-item. Models auto-load on startup with GPU/CPU auto-detection.
  3. Flutter App Development — Developed 9 screens: Login, Signup, Home (search + statistics dashboard), Report Item (with camera/gallery picker), Item Detail, AI Matches, Chat, Item Chats, and Profile.
  4. AI Integration — Connected the Flutter app to the AI server using Dio HTTP client. When a user uploads an image, it is sent to the /process-item endpoint which returns a caption + fused embedding.
  5. Matching System — Implemented cosine similarity matching locally in Dart. When viewing an item, the app fetches all opposite-type items and ranks them by embedding similarity.
  6. Chat & Messaging — Built a real-time chat system so item reporters and potential claimants can communicate directly within the app.
  7. Ownership Verification — Added a claim security flow where users must answer verification questions before an item is returned.
  8. Docker Containerization — Packaged the AI server in a Docker container with docker-compose.yml for one-command deployment.
